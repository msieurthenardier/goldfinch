# v0.19.15 — Vault and automation protections, and a fix for sites that rejected Goldfinch

This release makes the vault harder to read without you knowing, stops automation from reading your secrets without your say-so, and fixes a page-fingerprinting hook that made at least one airline site fail to load.

## Before you upgrade: your vaults

After you first unlock your vault on this version, your vault files are converted to a new file version (version 2) that earlier versions of Goldfinch cannot open. A bundle exported by this version cannot be opened by an earlier version either. The only way back is a copy of your vaults folder made before that first unlock, so copy it now: the `vaults` folder inside Goldfinch's data folder (Linux `~/.config/goldfinch/vaults`, macOS `~/Library/Application Support/goldfinch/vaults`, Windows `%APPDATA%\goldfinch\vaults`). Goldfinch keeps no backup of the old files, on purpose.

If you never use the vault, nothing changes for you.

## Added

- **A confirmation before automation can read a secret.** While an administrator-level automation client is attached (or a script it ran is still alive in the page), revealing a vault password, reading a one-time code, revealing a cookie value, exporting a vault, or creating an automation key shows a confirmation dialog that only you can answer. Cancel is the default. This was exercised by hand on Linux, and in automated runs. The dialog's handling of its window on Windows and macOS has not been checked.
- **The vault locks when your computer goes to sleep, and when Goldfinch quits.** On Linux, locking the screen does not lock the vault; only sleep does. Locking on sleep could not be tested on the machines this release was checked on.
- **Automation input no longer drives the browser's own shortcuts** (new tab, close, DevTools and so on) when the automation key is limited to one identity.
- **Where the automation server listens.** If it cannot use its configured port, the Automation page and the toolbar indicator now say which port it took.

## Changed

- **Electron 45.3.2** (from 44.10.0). The stores and the third-party-cookie isolation were re-checked on it.
- **A copied password or recovery key is cleared from the clipboard after about 20 seconds.** The clear that earlier versions were meant to do never ran; it does now (measured on Linux). It clears only if the clipboard still holds what Goldfinch put there. Clipboard managers, Windows clipboard history and the cloud clipboard are out of its reach.
- **Vault, database and crash-log files are readable only by you** where the operating system supports it (checked on Linux).
- **Internal pages (Settings and the like) are granted no permissions**, where before the runtime's default granted some, such as notifications and location (measured).
- **A new limit on automation sessions:** each key may hold eight at once, and starting a ninth ends that key's oldest.

## Fixed

- **Some sites that rejected Goldfinch now load.** With Shields' fingerprint protection on (the default), the way Goldfinch answered a page's graphics-card question could be told apart from a real browser, and one airline site's bot filter stopped answering. The answer now matches a real browser's in the cases checked. What a page can learn about your graphics card is unchanged. Checked on Windows, on the installed build. A profile that a site had already flagged before this fix may need that site's cookies cleared once (expected, not confirmed).

## Notes

- Not checked by hand: the clipboard clear and the quit lock on every platform, the vault conversion on Windows or macOS, and one-time codes behind the confirmation.
- Revoking an access key or changing the master password does not re-key your vaults. This is a known limit.
