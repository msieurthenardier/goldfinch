# v0.19.16 — Goldfinch tells you about new releases, and protects itself at launch

This release adds an update notice (it never downloads on its own), makes packaged builds refuse the command-line switches that switch off the browser's protections, and changes how releases are built and published.

## Added

- **Goldfinch tells you when a newer release exists.** About once a day it asks GitHub for the latest stable release and, if yours is older, shows `Update available` at the top of the ⋯ menu and in Settings → About. There is a **Download now** button, which starts an ordinary download of the installer for your computer (you run it to update), and a button that opens the release page. On Windows the button was seen starting a real download on a release candidate; on macOS and Linux it has not been seen. Goldfinch never downloads anything unless you press the button, and never installs or runs anything itself. Turn the check off with **Check for new versions** in Settings → About. The check sends no cookies and nothing that identifies you or your profile; GitHub sees your network address and your browser's language preference.
- **Five installers on every release, each with a provenance record.** Windows `.exe`, macOS `.dmg` and `.zip`, Linux `.AppImage` and `.deb`. Each has a SHA-256 digest on the release page and a build provenance attestation. The attestation step ran on three release candidates and was verified on Linux.

## Changed

- **A packaged build refuses some command-line switches.** Switches that turn off the browser's protections (for example `--js-flags` and the ones that disable site isolation) make Goldfinch exit with code 64 and a message naming the switch. Others (remote debugging, ignoring certificate errors, disabling web security) are ignored with a one-line note. `--no-sandbox` and `--proxy-server` still work. If a shortcut or script of yours passes one of the refused switches, it will stop starting the app. A development launch is unaffected.
- **Three Electron runtime features are turned off in installed builds:** running the program as Node, `NODE_OPTIONS`, and `--inspect`. The check passed on the Linux, Windows and macOS build runners, and the app started on all three.
- **Releases are published with no write access in the build step**, and a stable release must come from `main`'s history. A release no longer carries the updater files (`latest*.yml`, `*.blockmap`) or a checksum file. Releases are immutable once published.
- **Electron 45.3.3** (from 45.3.2).
- **A newer major version of a web-server library inside the automation transport**, to clear two security advisories. The tests that load it pass, and every automation tool answered in a live run on Linux.

## Notes

- **macOS users, please tell us.** The runtime change was checked on a macOS build runner (the signature verifies and the app starts there), but nobody has run it on a Mac. If the macOS build does not open on your Mac, please open an issue and say what the system showed. The build is Apple Silicon only and unsigned, so the first launch still shows a Gatekeeper warning: allow it through.
- **Verify your download.** Compare the SHA-256 digest on the release page with your file. With a recent GitHub CLI you can also run `gh attestation verify` (checked with version 2.104.0 on Linux; not run on Windows or macOS); the README shows the command. This shows the file was built by this repository's release workflow. It does not show the code is safe, and it is not an operating-system signature: Windows SmartScreen and macOS Gatekeeper will still warn.
- **Not changed, by decision:** cookies are stored unencrypted on disk, builds are not code-signed, and the code on disk is not integrity-checked. The README's *Known limits* has the reasons.
