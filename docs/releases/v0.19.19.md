# v0.19.19 — Closing tabs behaves, downloads keep their extensions, vault edge cases

This release tidies how tabs close, fixes several download and settings oddities, makes two vault operations cope with an unreadable vault file, and moves to Electron 45.4.1.

## Changed

- **Electron 45.4.1 (Chromium 156).** The app now runs on this Electron build. Checked on Linux in a development launch: windows, tabs, page loading, screenshots and page reading all worked.
- **Automation with an admin key now has to ask before a vault item is changed by way of an internal page** while that automation is attached or has run script in the page. The confirmation names the item by the title it had before automation touched it, so a rename cannot disguise it. Checked on Linux in a development launch with the vault unlocked.
- **The Automation page tells same-second sessions apart.** Each active session row now shows the first eight characters of its session id. Checked on Linux.
- **The client-certificate picker dims its list briefly after it opens**, as the vault picker already did, to show it is not yet taking clicks. Covered by automated tests; not yet checked by eye (see Notes).
- **Automation can press PageUp and PageDown.** Covered by automated tests.

## Fixed

- **Closing the active tab now selects its neighbour**, the tab that slides into its place, instead of jumping to the rightmost tab. Closing the last tab in the strip selects the one before it. Checked on Linux.
- **A second Ctrl+W no longer closes the whole window.** After closing the active tab from the page, keyboard focus is kept so the next Ctrl+W closes the next tab. Checked on Linux, including by eye.
- **The downloads popup keeps a long file name's extension visible.** The start of the name is shortened with an ellipsis instead, so `….exe` is still readable. Checked on Linux by eye.
- **A download started from the media panel that redirects keeps its suggested name and chosen folder.** Covered by automated tests.
- **Long file names can no longer grow past the length limit** when a number like ` (2)` is added to avoid overwriting a file; the extension is kept. Covered by automated tests.
- **A download that stopped with an error is no longer counted as still downloading** in the toolbar indicator. Covered by automated tests.
- **The Retry note on the Downloads page is accurate for a download Goldfinch started itself** (such as an update installer), and now points to Download now in Settings. Covered by automated tests.
- **A very long address after an in-page navigation no longer floods the address bar.** The address shown is cut at 8,192 characters; the page keeps its real address. Checked on Linux.
- **The automation Port field no longer shows a false "unsaved" hint** when the port Goldfinch is listening on differs from the saved one (for example when the port is set by an environment variable). The field always shows the saved port. Checked on Linux.
- **Older Settings switches can no longer be overwritten by a stale read.** Home page, Restore session, toolbar pins and spellcheck are now protected the way the update switch already was: a late initial read is dropped, and a refused save puts the last known value back. The bookmarks bar switch got the same treatment, covered by automated tests. Checked on Linux for the first group.
- **The home-page Save and Clear buttons line up** at the same height and top edge. Checked on Linux.
- **Developer tools state is restored after the browser window recovers from a crash**, so the tab's toolbar button matches. Covered by automated tests.
- **Exporting your vaults no longer fails entirely because one vault file is unreadable.** The readable vaults are exported and the notice says how many were skipped. Covered by automated tests.
- **Rotating keys after a suspected compromise no longer stops at the first unreadable vault file.** Readable vaults are rotated; the unreadable file is left untouched on disk, and the recovery card reports how many were skipped. A skipped vault cannot be opened with the new key, so restore it from a bundle. Covered by automated tests; the card's wording has not been checked by eye.
- **The vault file upgrade finishes at the first unlock** even when a leftover recovery file from an earlier interrupted write is present, rather than waiting one more unlock. Importing a vault whose key-derivation memory setting is too small for what the file claims is now refused with the vault's own error instead of failing deeper in. Both covered by automated tests.

## Notes

- Not checked on Windows or macOS. Linux checks were made in development launches (under WSL).
- Not yet checked by eye: the certificate picker's dimming, and the line on the recovery card that says how many vaults a rotation skipped.
- Nothing in this update changes how your settings, vaults or data are stored on disk.
