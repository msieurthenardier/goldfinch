## Objective

The release workflow publishes each release's title and text from a committed `docs/releases/vX.Y.Z.md` (a candidate borrowing its target's file, with the candidate title and opening line), falls back to today's generated notes on any problem without failing, never edits a published release, and runs no project code to do it; tests execute the workflow's own shell against every notes file and the edge cases; `npm test` requires the current version's notes file; the format guide, the release process docs and the backfill notes exist.

## Design review amendments — these override the text below wherever they differ

Developer design review 2026-11-18: **approve with changes** (three high, four medium, four low), all incorporated. Second review pass skipped by Flight Director call: every change below is the reviewer's own prescription, and the flight-end Reviewer covers the code.

1. **The step runs under `-eo pipefail` (high).** `build.yml:124` gives the draft step `shell: bash`, which GitHub runs as `bash --noprofile --norc -eo pipefail {0}`. "No `set -e`" in Context and DD2 is wrong. Every notes-logic command that can fail is guarded (`if ! gh api … > "$f"; then …`, `split_release_notes … 2>"$err" || reason=…`, `x=$(gh release list …) || x=''`); the function does not rely on `-e` (explicit `|| return 1`, since `-e` is suspended inside a function called from `if`/`||`). **AC4 runs the extracted script exactly as the runner does**: `bash --noprofile --norc -eo pipefail <scriptfile>`. Added scenario: `gh api` exits non-zero and the step still reaches `create --generate-notes` and the summary line. When `gh api` fails, the temp file is removed and the splitter is not called (reason `missing-or-unreadable`, never `empty-body`).
2. **Release state is read from the list, not `gh release view <tag>` (high).** `gh release view <tag>` uses the by-tag endpoint, which may not return drafts (unconfirmed offline). Primary read: `state=$(gh release list --repo … --limit 200 --json tagName,isDraft --jq '[.[] | select(.tagName == env.GITHUB_REF_NAME)] | if length == 0 then "none" elif .[0].isDraft then "draft" else "published" end') || state=''`. `none` → create (notes or fallback); `draft` → edit title and text if notes found, else leave; `published` → nothing; empty (the list read failed) → today's exact logic: `gh release view` existence check, reuse **without any edit** if it exists, else create (notes if found). The live draft re-edit stays **unproven** until a real re-run on a draft (the walk's first candidate has no existing draft); say so in the flight log.
3. **AC7 path patterns (high).** Drop the bare `~/` rule (it rejects `~/Library/Application Support/goldfinch`, the macOS data folder). Keep `/home/`, `/Users/`, `C:\Users\`, `\\Users\\`, `/tmp/`, `/var/folders/`. Add a positive test: the three real per-OS data-folder strings (`%APPDATA%\goldfinch\vaults`, `~/.config/goldfinch/vaults`, `~/Library/Application Support/goldfinch/vaults`) pass the check.
4. **Control bytes without pipes (medium).** No `head | tr | grep -q` pipeline (under `pipefail` an early `grep -q` exit can SIGPIPE the writer and read as clean). Write line 1 to a temp file, strip `\r` into another, `LC_ALL=C grep -q '[[:cntrl:]]' file` (probed: catches `\x01`, tab, DEL, VT on GNU grep 3.11; NOT NUL). **NUL anywhere in the file** is a separate check: `[ "$(tr -d '\0' < f | wc -c)" -eq "$(wc -c < f)" ]` → fallback `control-byte`.
5. **Tabs (medium).** A tab in the title line is rejected (AC2 stands); DD2's "except `\t`" is superseded (the Flight Director updates DD2).
6. **Candidate edge tags through the step (medium).** AC4 adds `v1.2.3-alpha-1` and `v1.2.3-rc.1+b2` (both candidates, base `1.2.3`). The stub serves ONLY `contents/docs/releases/v1.2.3.md` (or the scenario's one file) and 404s every other path, so the "base → core" neuter really fails.
7. **Fixtures (low).** Add the exactly-65,536-byte pass case; the 200-byte em-dash title (`v1.2.3 ` + 64 em dashes + `x`) passes and 201 fails; title length measured in bytes under `LC_ALL=C` inside the function; a body with a later `# v…` line; a title containing `$(touch x)` and backticks, asserting no side-effect file appears.
8. **Extraction (low).** Reuse `runBodiesOf(stepOf(…))`, dedent to the minimum common indent before writing the script file; no heredocs in the step; keep the step name `Create the draft release (idempotent)`. The `${{` pin targets the run body only (`env:` legitimately has `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`). The stub distinguishes `api`, `release list`, `release view`, `release create`, `release edit`.
9. **Platform gating (suggestion, adopted).** The executing tests skip unless `bashOk && process.platform === 'linux'` (GNU sed `\x` escapes); the reason is stated in the skip text. Text pins and `release-notes.test.js` run everywhere.
10. **Non-vacuous (suggestion, adopted).** `release-notes.test.js` asserts at least one `v*.md` exists. Added AC4 scenario: existing draft + notes, `gh release edit` fails → the step fails (as today).

- [ ] **AC2 — splitter rules** exactly as DD2: size ≤ 65,536 bytes checked first (`wc -c`); no control byte at all in the first line (a tab included) apart from its line ending `\r\n`/`\n` (checked on the file, so a NUL is caught); a leading UTF-8 BOM and every `\r` removed; first line `# ` + a title starting `v${base} ` with text after it, ≤ 200 bytes, no trailing space; body = everything after line 1 with leading blank lines trimmed, containing a non-whitespace byte. ## Implementation Guidance

2. Byte-safe shell: `LC_ALL=C`; size with `wc -c < "$f"`; control bytes in the first line with `head -n1 "$f" | tr -d '\r' | LC_ALL=C grep -q '[[:cntrl:]]'` (NUL: check with `head -c` + `tr -d '\0' | wc -c` comparison or `grep -qaP '\x00'` — pick one that works on GNU grep and prove it in a fixture); BOM with `sed '1s/^\xEF\xBB\xBF//'`; trim leading blank lines with `sed '/./,$!d'`.

The stub `gh` is a small bash script written to the temp dir; it must not be able to reach the network (it is a file named `gh` first on `PATH`; assert the real `gh` is never called by making the stub the only `gh` the test's `PATH` can find — e.g. `PATH=<stubdir>:/usr/bin:/bin` and check `command -v gh` resolves to the stub inside the run).
4. Keep the existing `expected_names` tests' meaning; refactor `functionTexts` minimally.

## Edge Cases

- `GITHUB_SHA` is a branch commit for a candidate (the file is read from the branch, not `main`) — intended.
- A notes file present on `main` for a version ahead of `package.json` (written before the bump) — allowed by AC7.
- A title containing `$`, backticks or quotes — passed as a quoted variable; include one in a fixture.
- A body containing a line `# v…` later on — only line 1 is the title.
- `isDraft` read prints `false` → published branch; prints nothing / errors → no edit.
