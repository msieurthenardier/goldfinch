# CLAUDE.md

Goldfinch — an Electron desktop browser with a media panel (scan/play/download page media) and a privacy panel (Shields + cookie-jar identities).

## Commands

- `npm start` — run the app
- `npm run dev:automation` — canonical dev launch (`scripts/dev-launch.mjs`, WSL/headless friendly); dev-only, profile-isolated. Add `GOLDFINCH_AUTOMATION_ADMIN=1` when admin-tier MCP ops are needed. **Two consumer models, don't conflate**: script harnesses that re-capture the printed key each run add `GOLDFINCH_AUTOMATION_DEV_MINT=1` per launch (prints one parseable `AUTOMATION_DEV_MINT {"key":"<jarKey>","adminKey":"<adminKey>"}` line, both keys shown once) and attach via env-key scripts (`scripts/lib/mcp-client.mjs`); MCP clients holding a standing token in a static config (e.g. a `.mcp.json` entry — a legitimate, documented attach path) mint ONCE, then relaunch WITHOUT `DEV_MINT` — every re-mint **replaces** the stored per-jar/admin key hash, so a stale static config starts 401ing. Launch states, key capture, attach recipes, ozone/WSLg notes, web-compat triage order: `docs/dev-testing.md`; full MCP reference (incl. `.mcp.json` registration): `docs/mcp-automation.md`. **Operator standing preference**: behavior tests and live smokes run in Goldfinch dev mode (`dev:automation` + `GOLDFINCH_AUTOMATION_DEV_MINT=1`, key captured per launch, `connectAutomation()` env-key scripts) — never the registered `goldfinch-dev` MCP server.

## Architecture

Three processes; understand the boundary before editing.

- **Main** (`src/main/`): `main.js` is the composition root, not the behavior owner. `window-factory.js` builds windows/chrome views and owns close teardown; `window-registry.js` owns records `{win, chromeView, tabViews, activeTabWcId}`; `register-{tab,overlay,download,settings,browser}-ipc.js` own channel families; `app-lifecycle.js` owns ready/restore/quit; `session-runtime.js` owns web-session policy and retention cadence; `internal-ipc.js` is the origin-checked bridge for trusted `goldfinch://` pages.
  - **Main↔chrome routing has three classes — classify any new send/handler site first**: (1) sender-resolved inbound (`registry.getWindowForChrome(event.sender)` / `getWindowForGuest(event.sender.id)`); (2) broadcast fan-out (`broadcastToChromeAndInternal`: all chromes + internal-session contents, once); (3) per-tab owner-routed pushes, resolved at EVENT TIME via `getChromeForTab(wcId)` (this makes move-to-new-window re-bind automatic). Never fan out a per-tab push or use a focused-window accessor; `getChromeContents()` is last-focused only — don't build on it.
  - **Every main-process IPC channel is registered through a named caller class** (`ipc-gate.js`, constructed once in `main.js`, handed to registrars; Mission 23 Flight 1). A page in a tab could come to hold the guest preload's IPC object (measured on Electron 44.10.0, probe Q1: once main sends the tab any message; on 45.3.2 the known probe no longer reaches it, which is not proven closed), so **no preload-side measure is a boundary — the main-side caller class is**: literal preload sends (`test/unit/preload-channel-literals.test.js`) are hardening that keeps the guest's surface readable, nothing more. Classes (`CHANNEL_CLASS` in `ipc-channel-table.js`, 211 rows, one per channel): `gate.chrome`; `gate.owningChrome` (the registration supplies a defensive tab-id extractor — an extractor throw is a refusal; a named tab must be a tab of the SENDER's window, a non-numeric id or a non-tab webContents is refused, "no tab named" passes as chrome-only); `gate.chromeOrInternal`; `gate.tabGuest` (the sender's own MAIN frame — compared by frame-tree node id in a `try`, never `parent === null` — and a web tab in some `tabViews`; per-registration switches `popups` / `internalTabs` / `activeOnly`, each stated at the call site, default off; the synchronous `.sync(…)` form takes a mandatory refusal and sets `returnValue` on EVERY path, so a refused or throwing handler never blocks a page load); `gate.sheet` (sender is the window's sheet AND the current menu type is in the channel's row of `SHEET_MENU_TYPES`, or `'any-open-menu'`, or `'sender-only'` for `menu-overlay:sheet-drag` alone; a refused invoke zeroes every byte array it carried); `gate.find`; `gate.savePrompt`; `gate.findOrOwningChrome` (`find-overlay:close`); `registerInternalHandler` stays the `internal` class. Invoke forms state their refusal explicitly (`'throw'` or `{ value }`, no default; a refused invoke that throws makes Electron print its own handler-error line — channel and source path, no arguments — which is accepted); one-way forms drop a refused message; the handler keeps `(event, ...args)`; a null `senderFrame` is refused. A channel not in the table, or registered under another class, throws at registration (boot). `shields-farble`'s refusal value is farbling ON with a per-call random seed — it is NOT a protection against the page itself (an admitted main-frame page can read its own session's seed). `GOLDFINCH_IPC_TRACE=1` prints one line per refusal (channel, class, sender kind; never arguments). `test/unit/ipc-gate-invariant.test.js` scans `src/main/**` and fails on ANY raw `ipcMain.handle`/`.on` (the exception list is empty and pinned at 0; there is no `LEGACY`), a non-literal channel, an `ipcMain` token outside the enumerated contexts (a registrar that registers nothing raw takes no `ipcMain` parameter), table/scan drift, a sheet registration not taking its menu types from its own table row, or a tab-guest registration whose switches differ from the pinned table. Registrar unit tests build a REAL gate via `test/helpers/ipc-gate-fixture.js` (`makeTestGate`, `eventFrom`, `guestEvent`).
  - **Close order** (`window-factory.js`, at `close`): find overlay → tear-off overlay → sheet → closed-tab capture/session snapshot → per-tab side effects + **explicit guest destroy** (Electron never auto-destroys an attached view's webContents). `closed` removes the record. Closing one of N windows never quits.
  - **⚠️ Never read `win.*` inside `closed`-or-later handlers** — capture inputs (`const winId = win.id`) at create time. A destroyed-`BaseWindow` access throws, and an uncaught throw in the native `closed` emission aborts the listener chain and permanently wedges the Wayland close path with no error output (`window-closed-invariant.test.js`: no raw `.on('closed'` in `src/main/**`).
- **Preloads** (`src/preload/`): `chrome-preload.js` exposes `window.goldfinch.*`. `webview-preload.js` runs in every web page's **main world** (media scanner, fingerprint farble) and drives an **isolated world** for vault-capture reads immune to page accessor spoofing. `internal-preload.js` is context-isolated, exposes `window.goldfinchInternal` behind an `INTERNAL_ORIGINS` check (defense in depth; main-side `registerInternalHandler` is authoritative). Keep the three separate.
- **Renderer** (`src/renderer/`): `renderer.js` is the chrome boot root; `chrome/*-controller.js` own behavior; `chrome/overlay-dispatch.js` owns the generic sheet-activation switch. Tabs are addressed by `wcId`. Menus/dialogs render from the main-owned **menu-overlay sheet**, not chrome DOM.

Cross-cutting facts:
- **Shields apply to every jar via `session-runtime.js`'s `onSessionCreated`** (each container/burner/default tab is a session partition); one `webRequest` listener per event per session shared by recording and enforcement.
- **Third-party cookie isolation is native, not header-stripping** (sortie 02): Chromium's `ForceThirdPartyCookieBlockingEnabled` blocks unpartitioned 3P cookies on HTTP and `document.cookie` while CHIPS `Partitioned` cookies keep working. It is decided BEFORE `app.ready` (`main.js` startup block → `shields-startup.js` read-only peek of the persisted config via `app-db.peekDocumentReadOnly`, composed by `third-party-cookies.js` `decideStartup`), is **process-wide and restart-to-apply** (no per-site pause, no live toggle), and `isolateEffective` is a **process constant** (threaded to `session-runtime.js`, the permission gates and the `shields-isolation-state` channel) that can differ from `shields.get()` until restart. The ONE `appendSwitch('enable-features'` in `src/main/**` (order/uniqueness pinned by `third-party-cookie-startup-order.test.js`) composes with the operator's own `--enable/disable-features`. `onHeadersReceived` no longer touches cookies — it only counts a domain as isolated when a third-party non-main-frame response carries a `Set-Cookie` that isn't `Partitioned; Secure`; request-side withholding is unobservable. `storage-access`/`top-level-storage-access` are denied while `isolateEffective`.
- **Restart-to-apply UX** (sortie 02 leg 2): `src/shared/shields-isolation-model.js` (pure; single-sources the copy, `effectiveAfterRestart` — drift-guarded against `decideStartup` and the CJS `effectiveAfterRestartFromConfigured` in `third-party-cookies.js` — plus the two-step `createRestartConfirm`) drives BOTH the privacy panel and `goldfinch://settings`. The panel's Shields section is a **persistent node** (`chrome/shields-section.js`, `#privacy-body`'s first child, **patched in place by `data-shield` key, never rebuilt** — `renderPrivacy` removes every other child; switch clicks read LIVE config) so focus survives network pushes. **Reload to apply** is hidden unless the active eligible web tab has `tab.privacy.reloadStale` (set on every eligible web tab by the single `applyShieldsConfig` on an `enabled`/`block`/`strip`/`farble`/`pausedSites` change, never `isolate` or the boot resolve; cleared when `renderer.js` replaces `tab.privacy` on navigation, or on the button's own reload). **Restart now** (`shields-restart-to-apply` / `internal-shields-restart-to-apply`) is sender-validated + main-side business-gated (`not-pending` → no-op), takes no args, and on pass runs: delete `GOLDFINCH_AUTOMATION_DEV_MINT` from the live env → `releaseSingleInstanceLock()` → `relaunch(relaunchOptions({env}))` (`APPIMAGE`→`execPath`; Electron has no relaunch `env`) → `quit()`. No MCP op (admin chrome `evaluate` reaches it like `appQuit`). The isolate row shows what is IN FORCE (`isolateEffective`), never dimmed/uncounted while enforced; per-site pause doesn't cover it (`Applies browser-wide` note).
- **Permissions are positive-allowlist on web sessions and deny-all on the internal session** (`session-runtime.js`, Mission 23 Flight 2): Electron GRANTS when no handler is installed (measured: notifications, geolocation, camera, microphone, `window-management` all `granted` on a `goldfinch://` page), so `onSessionCreated`'s internal branch installs a request and a check handler that answer `false` for everything and send no `privacy-permission` message; `window-management` is NOT in `ALLOWED_PERMISSIONS` (nothing in `src/` uses it). An internal page that needs a permission needs a design decision, not an allowlist entry. The chrome and overlay views have no partition, so they share the default session and its web handlers.
- **Web guests run `contextIsolation:false`** (farbling needs the preload in the page main world) with `nodeIntegration` off, `sandbox:true` and `autoplayPolicy: 'document-user-activation-required'` (tab + popup); web sessions send Electron's default UA minus ONLY the `goldfinch/<ver>` app token (a near-unique fingerprint; `user-agent.js` `stripAppToken`, the one `setUserAgent` site, in `onSessionCreated`; squawk 0169) — never strip the `Electron/` token or spoof a plain-Chrome UA (Cloudflare's managed challenge loops on the inconsistency; squawk 0145); internal views are context-isolated + sandboxed; the chrome view is the one tracked sandbox exception. Farble config is read synchronously at page load — toggling needs a reload. Guest-preload sends are string-literal channels (hardening only — a page that holds the IPC object can name any channel; measured reachable on Electron 44.10.0, not by the known probe on 45.3.2, not proven closed); the boundary is the main-side `tab-guest` class: a web tab's MAIN frame, popups admitted only for `shields-farble` / `vault-eligible` / `guest-window-close`, the active tab only for `guest-tab-boundary` (an internal tab may send that one). `guest-privacy-fp` forwards only a validated object (`src/shared/privacy-fp.js`: fixed key set, non-negative integers clamped, anything else dropped whole).
- Persisted state: `userData/app.db` (see App database); legacy JSON imports once and is renamed `.migrated`. The **session snapshot is written continuously (debounced)** by `session-snapshot-scheduler.js`; `isRestorePending` gates writes during boot restore; `before-quit` flushes the timer first so nothing fires after `appDb.close()`. The **vault** is a separate substrate (`userData/vaults/`).
- **⚠️ `WebContentsView` native-surface gotcha — "DOM correct ≠ render correct."** A guest view is an out-of-process native surface: bounds/visibility changes can mis-render composited pixels while every `getComputedStyle`/`getBoundingClientRect` looks right. A guest bounds change is a discrete `setBounds` STEP, not animatable. **INVARIANT: never animate chrome layout that resizes/repositions the guest slot; animate only things that float OVER the guest (find bar, sheet), or make the layout change instant.** The acceptance signal is a human watching the rendered surface in motion; spike on-platform first; don't blame WSLg without a cross-platform control.

## Patterns

### `src/shared/` ESM modules

Real ESM with explicit `.js` extensions, loaded via `<script type="module">`; unit tests `require()` the same file (Node ≥22), so tests run shipped code.

- **Two specifier shapes, by consumer.** `file://` chrome imports disk-relative; internal `goldfinch://` pages import **flat** specifiers (`./safe-color.js`) because `internal-page-map.js` is an exact-match map (a disk-relative specifier 404s at boot). Flat imports carry `// @ts-ignore`, typed `any`.
- **CJS-by-design quartet + eslint parse guard.** `automation-dev.js` and `internal-page.js` are preload-reachable (no `require(esm)`) and MUST stay CJS; `dev-profile.js` and `guest-forward-allowlist.js` stay CJS by ruling. `eslint.config.mjs` binds all four to `commonjs`; the later `src/shared/**` block's `ignores` entry for them is **LOAD-BEARING** (later-wins would otherwise delete the parse guard).
- **Renderer evaluate-seam closed-set rule.** Controller code stays module-scoped; `renderer.js`'s tail republishes exactly the FD-approved set with `Object.assign(globalThis, {…})`. The set is **41 entries** (`SEAM_COUNT`, `test/unit/seam-contract.test.js`); it changes only by FD ruling, updating the test constant and this line together.
- **Defer/module pin.** Every classic `<script>` on a page that also loads a module script must carry `defer` (`menu-overlay.html`'s `menu-controller.js` is the one carve-out).
- **New-shared-module checklist**: module script tag only; internal-page consumers need an exact `internal-page-map.js` route; a new `src/renderer/pages/*.js` controller also needs its own entry in `eslint.config.mjs`'s explicit module-`sourceType` file list (only `chrome/**` is a glob — a missing page entry fails lint as a script parse error); evaluate-reachable entry points go through the seam; a new contextBridge method needs its `renderer-globals.d.ts` entry.
- **Page controllers take `src/shared/` pure functions as injected deps.** Controllers under `src/renderer/pages/` receive them as arguments (exemplar: `vault-filter-controller.js`) so unit tests execute them against a mock DOM; a static flat-specifier import resolves only through the internal-page map, leaving the file source-scan-testable only.
- **Grep-AC convention.** Negative/invariant ACs may be a literal reproducible grep/diff with each hit judged exempt-or-real, instead of a unit test.
- **Regex-target mutation pins.** When a source-text pin's `.replace()` target would be an exact multi-line literal, use a wrap-insensitive regex (`\s+`/`\s*`, metacharacters escaped) with a captured-indent replacer so a Prettier re-wrap can't stale it. Keep `assertMutated` guarding every mutation (a no-op `.replace()` passes vacuously). Dispatch-table scans need a bounded non-greedy lookahead (`(?:(?!\n\s*\w+:)[\s\S])*?`). Exemplars: `move-authority.test.js`, `tab-drag-invariants.test.js`, `sheet-automation-gate-invariant.test.js`; re-targets are neuter-verified.
- **MockTimers recipe.** Enable per test (`t.mock.timers.enable(...)` in the test body, never file-global); drain with real `setImmediate` around single-step ticks, never one big tick. Exemplar: `test/unit/automation-find.test.js`.

### Two-point hostile-URL security boundary

`isSafeTabUrl` is enforced at the renderer `createTab` gate (only `http:`/`https:`/`about:blank`) and the main `will-navigate` guard. **NEVER widen it to admit `goldfinch://`.** `tab-create` additionally re-validates its arguments main-side BEFORE choosing `webPreferences` (`tab-create-validate.js`): `trusted` exactly `true`/`false`, a trusted create names an internal page only, an untrusted one an `isSafeTabUrl` URL in a registered jar's partition or a burner by exact shape (`burner:<digits>`) — never `INTERNAL_PARTITION`; a restore's entries that fail `isSafeTabUrl` are DROPPED, not a reason to refuse (the rest restore, `index` re-pointed to the surviving entry nearest the original position, the earlier on a tie; no survivor = a plain create of the tab's `url`), while the entry count cap, the `index` check against the ORIGINAL list, the safe `url`, the partition predicate, exact-boolean `trusted` and "no restore on a trusted create" still refuse; a refused create returns `null` and builds no view. `identity-new` uses the same partition predicate.

**Credentials never reach the address bar** (leg `prompts-and-bounds`, widened in the flight-end fix pass): the pure `src/shared/display-url.js` `displayUrl` removes `user:pass@` from every URL main pushes to the chrome for display — `did-navigate` / `did-navigate-in-page`, the load-failure push (`failureForChrome`), the `tab-crash` push (`crashForChrome`, both sites) and the window-move / recovery adopt payload (`buildAdoptPayload`) — and from what history stores, and ONLY there. The chrome is therefore told, and the automation tab census (built from the chrome's tab state) reports, the address WITHOUT `user:pass@`. Navigation, reload, the session snapshot, closed-tab capture, tab moves (the move re-parents the existing view) and load-failure Retry use the real address held in main: the panel's Retry names the display form, and `tab-navigate` restores the credentialed address THIS tab recorded for the failed load (`restoreRecordedCredentials`) ONLY while that tab is showing the load-failure panel for that address — exact display-form match against the failure's own recorded address; a tab with no failure record, a different typed address, or a failure address without credentials is never rewritten, and the last-requested address is not a candidate. One narrow case is accepted: on a tab showing the failure panel, pressing Enter on the cleaned address in the address bar is indistinguishable from the panel's Retry and also re-requests the recorded address. Such a URL still loads and authenticates (source-scan pinned in `display-url.test.js`). Two accepted behaviours: pressing Enter in the address bar on a cleaned address navigates WITHOUT the credentials, and bookmarking a page reached with credentials stores the cleaned address (an older bookmark that includes credentials no longer shows as starred on that page). The `tab-title` push carries `capTitle` (512 characters).

**PDF-viewer carve-out — the ONE relaxation**: `guardNav` stays strict on `will-navigate`/`will-redirect`/`will-frame-navigate`; only the `will-frame-navigate` registration is a wrapper that also allows a **subframe** (`isMainFrame === false`, fail-closed when absent) on a **non-internal** guest whose URL is scheme `chrome-extension:` with host exactly `PDF_VIEWER_EXTENSION_ID` (`guest-wiring.js`). Web guests carry `plugins: true`, internal guests don't. Top-frame `chrome-extension:` stays refused; never widen (matrix in `guest-wiring.test.js`).

### Recurring module shapes

- **Electron-free, injected-deps modules** (main-side): live handles passed as arguments, never `require('electron')`, so logic runs under `node --test` with fakes (`automation/engine.js`, `settings-store.js`, `menu-overlay-manager.js`). Pure decision modules live in `src/shared/`; a main-only one stays CJS.
- **Drift guard**: a constant/table asserted equal to another module's DERIVED value so a new entry on one side goes red until the other catches up (`identity-profile.test.js`, `vault-editor-model.test.js`, `vault-page-model.test.js`, `bookmarks-bar-css-pin.test.js` — the source-scan flavor throws rather than passing vacuously).
- **Planner/actuator split**: a pure planner returns independent actions; a thin loop runs each in its own `try`/`catch` with **no early return inside the loop**, so one failure never stops the rest (`planCaptures` + `onCaptureGesture`).
- **Cast-to-local before a chain.** Never put an inline `/** @type {any} */ (x)` cast inside a multi-line chain/argument list/ternary (Prettier reattaches the comment); bind `const anyX = /** @type {any} */ (x);` first. `// @ts-ignore` covers only the NEXT line, so on a multi-line import it goes right before the `} from '…'` line.
- **Decide tab type with `isInternalTab()`/`isWebTab()`, never by reading `.trusted`** (trust is call-site provenance at `createTab`).

### Internal `goldfinch://` pages — trusted-embedder security model

Internal origins (`settings`, `downloads`, `jars`, `vault`, `automation`) are equally privileged: the trust boundary is **"internal vs web," never per-page**. Security-critical.

- **The welcome surface is NOT an internal page** — a chrome-owned viewless tab (`welcome-controller.js`) with no `goldfinch://` URL. Its DOM ids/classes (`#welcome-*`, `.welcome-engine-row`) are a frozen contract (`search-engines.test.js`): restyle may wrap, never rename/remove/re-toggle.
- `goldfinch` is registered privileged (`{standard: true, secure: true}`) before `app.ready`; `standard: true` is load-bearing. Served from a dedicated in-memory internal session with a **session-scoped** `protocol.handle`. **`INTERNAL_PARTITION` is single-sourced** in `src/shared/internal-page.js` — import, never re-type (drift makes every gate fail open).
- **CSP is stamped IN the response** (`INTERNAL_CSP`) — custom-protocol responses bypass `onHeadersReceived`. Don't relax without security review.
- **Route map** (`internal-page-map.js`): exact host → pathname → file; no path arithmetic, no directory passthrough.
- **The four gates**: (1) trust is call-site provenance — `createTab(url, container, { trusted: true })`, never inferred from the URL, and `onOpenTab` passes no flag; (2) trusted branch validates with `isInternalPageUrl`, untrusted with `isSafeTabUrl`; (3) session-aware `will-navigate`; (4) the protocol handler exists on the internal session alone.
- **Chrome-fetch invariant: no page-controlled URL is fetched by the chrome outside the owning jar's session.** Chrome CSP forbids remote `img-src`/`media-src` (`csp-pins.test.js`); favicons are fetched main-side and delivered as `data:` URLs; media-panel remote URLs go through the **`goldfinch-media:`** proxy (default session only, `toMediaProxyUrl`, forwarded via the guest's OWN session, streaming). Never assign an `http(s):` URL directly in `media-controller.js`. **The proxy is addressed by a per-tab, per-document TOKEN, never a tab number** (`goldfinch-media://proxy/<token>/<url>`; `media-proxy-tokens.js`, 192-bit base64url): main mints it when a tab's media list arrives, bound to the main frame's frame token; a list whose sender frame is not the current main frame is DROPPED (an old document's last list can arrive after `did-navigate`); `did-navigate` invalidates unless the token was already minted for the now-current document; `destroyed` drops it; the store is the single authority (`resolveToken` on the handler — unknown, replaced and decimal-number addresses all 404). The token rides the existing `tab-media-list` push to the chrome only, is never sent to a guest and never logged. **The media list is validated in main** (`media-list.js`, at the `guest-media-list` registration — the chrome only receives its output): explicit field list, http(s) URLs plus raster `data:` images on image items only; `toMediaProxyUrl(token, url)` answers `null` for anything else and every chrome sink assigns nothing for `null`. `download-media` accepts only http(s), `blob:` and raster `data:` images, and its pending record is keyed by downloading tab + URL, consumed at download start. A history title update matches the visit's id, jar, URL **and** timestamp (`history-store.js` `setTitle`), so a reissued row id can never retitle another visit.
- **Adding an internal page**: entry tree in `internal-page-map.js`; host in `INTERNAL_HOSTS`; origin in `INTERNAL_ORIGINS` (`internal-ipc.js` AND `internal-preload.js`); chrome-side tab name in `INTERNAL_JAR_NAMES` (`tab-controller.js`); open via the trusted `createTab` path (kebab item + action in `overlay-menus.js`). `internal-page-route-closure.test.js` and `internal-host-drift.test.js` (hosts === map keys === both origin sets === `INTERNAL_JAR_NAMES`) are the standing guards.

### Internal-bridge security model (`src/main/internal-ipc.js`)

`registerInternalHandler` checks BEFORE the handler: `INTERNAL_ORIGINS.has(event.senderFrame?.origin)` (destroyed frame → `null` → fails) AND `event.sender.session.__goldfinchInternal === true`. This is the authoritative boundary.

- **A read-only channel consumed by BOTH the `file://` chrome and an internal page is registered with `gate.chromeOrInternal`** (exemplar `automation:get-activity`) — never a bare `ipcMain.handle`, which any page that holds the guest preload's IPC object (measured on 44.10.0; not reached by the known probe on 45.3.2, not proven closed) could call, and never `registerInternalHandler`, which fails the chrome's `file://` origin. A chrome-only read (`settings-get`, `shields-get`) is `gate.chrome`. **The chrome never receives an automation key hash**: `settings-get` and the `settings-changed` broadcast carry a main-computed `automationKeyState` (`{ jarIdsWithKey, adminKeyEnabled }`, `settings-chrome-view.js`) instead of `automationKeyHashes`/`automationAdminKeyHash`; `internal-settings-get` and the store API still return the hashes to internal pages.
- **`internal-settings-set` never writes a key hash**: `automationKeyHashes` and `automationAdminKeyHash` are refused there for every caller (fixed message, before `settings.set`, nothing written or broadcast) — mint and revoke (main-side, through the store) are the only writers, so the launch flag stays the only door to the admin tier. A key-map entry under a reserved identity name (`isReservedKeyName`, `src/shared/reserved-ids.js` — the one predicate shared by the store, `validateKey`, `mintJarKey`, `settings-chrome-view.js` and `jars.js`) is never an identity: `set` rejects it, `load` strips it per entry and persists once, `validateKey` skips it.
- **Any handler that mutates settings directly must broadcast `settings-changed`** (`broadcastToChromeAndInternal`); only `internal-settings-set` does it automatically. `chrome-welcome-set` is the one chrome-initiated settings write (only `homePage`/`searchEngine`).

### Downloads (`register-download-ipc.js`, `download-path.js`, `download-retry.js`)

- **Records carry their partition** (a string, absent for the browser's own session): taken in `will-download` from a session→partition `WeakMap` that tab creation writes (`tab-create`, web branch — a burner session has no storage path) and Retry writes, falling back to `partitionFromStoragePath` for persistent jars. - **`sanitizeFilename`** replaces control, Unicode format (bidi, zero-width, BOM, soft hyphen), line/paragraph separator and lone-surrogate characters with `_` FIRST (as Chromium does in names it derives; losing a zero-width joiner in an emoji or Persian/Indic name is accepted), tests the trimmed first dot-segment for reserved device names, and truncates in UTF-8 bytes keeping a final 1-16 character extension.

### Menu-overlay sheet

- **Protocol**: chrome→main open/close carry a chrome-minted monotonic token (stale tokens dropped); main→chrome `menu-overlay-closed` (7) is emitted BEFORE `menu-overlay-activated` (6); `:activated` `value` is sanitized (≤24 chars). ### Password vault

### Auth challenges (HTTP basic auth + client certificates)

`src/main/auth-challenges.js`: one Electron-free store behind `app.on('login')` and `app.on('select-client-certificate')` (both unconditionally `preventDefault()`ed), per-window FIFO queues, presented as `auth-basic`/`cert-picker` sheets.

Close reasons are **resolution** (escape/outside-click/activated/tab-close/teardown, and the default for unknown) or **occlusion** (blur/superseded/tab-hide/tab-switch — re-presents later). Never add a close path that can leave a callback dangling.
- **The realm is cleaned in main before it is stored** (`cleanRealm`, leg `prompts-and-bounds`): whitespace collapsed, control/format characters and every double-quote form removed (a realm cannot close the card's quote and continue in the browser's voice), capped at 120 characters with an ellipsis; an empty result reads as no realm.

### Non-obvious gotchas

- **`asar:false`** — `src/**` must stay unpacked (internal-page `path.join(__dirname, …)` resolver).
- **Node-vs-Blink origin**: Blink serializes the `goldfinch` scheme origin as `goldfinch://settings`; Node's `new URL(...).origin` is `'null'`. Do NOT "fix" `INTERNAL_ORIGINS` to match Node.
- **Electron `findNext: true` means START A NEW find session**, not step (main maps same text + Enter → step, changed text → new session).
- **Focus-then-send**: a branch forwarding a keyboard-expecting action to the chrome view must `getChromeContents()?.focus()` BEFORE `.send(...)`.
- **Patch in place, never rebuild, whatever holds `document.activeElement`** on broadcast-rendered pages (a rebuild loses the caret and fires a spurious commit-on-blur).
- **Real-boot defects `npm test` can't catch**: `mkdirSync`-before-synchronous-persist (`app-db.js`'s `open()` does it once; unit fixtures pre-create dirs) and classic-script scope collisions.
- **Vault stores load loudly**: a tampered/unknown-version `.gfvault`/`manager.json` throws and is NEVER quarantined (opposite of `app.db`).
- **Packaged builds have three runtime fuses off** (`package.json` `build.electronFuses`: `runAsNode`, `enableNodeOptionsEnvironmentVariable`, `enableNodeCliInspectArguments`; `resetAdHocDarwinSignature` re-signs macOS): a packaged binary cannot be run as Node or opened with `--inspect`, and the dev binary is unaffected. `scripts/check-fuses.mjs <binary>` pins the whole fuse table and runs after packing in `ci/tasks/package-linux.yml` and `ci.yml`; `docs/RELEASING.md` *Runtime fuses*. **Never launch a packaged build on a dev host without BOTH `HOME` and `XDG_CONFIG_HOME` redirected** (`docs/dev-testing.md` *Packaged build on a dev host*).
- **Launch switches (Mission 23 Flight 3, leg `launch-switches`; `src/main/launch-switches.js`).** A packaged build does not obey the command-line switches that turn off its protections: pure `decideLaunchSwitches` / `applyLaunchSwitches` over two frozen tables (*stripped*: `app.commandLine.removeSwitch` before `ready`, measured to stop the effect; *refused*: one stderr line + `dialog.showErrorBox` + `app.exit(64); process.exit(64)`), asking `app.commandLine.hasSwitch`, never re-parsing argv. The one block in `main.js` sits after the dev `setPath('userData'` redirect and BEFORE `requestSingleInstanceLock()` (a refused launch takes no lock, opens no store, hands nothing to a running instance) and before the `enable-features` reader; it contains no `appendSwitch`; `removeSwitch(` appears nowhere else in `src/main/**` (`launch-switches-placement.test.js`). `--disable-features` is refused only when it names `IsolateOrigins`/`SitePerProcess`/`site-per-process`. `--allow-file-access-from-files` is on NEITHER list (Electron adds it itself while the `GrantFileProtocolExtraPrivileges` fuse is on, so `hasSwitch` is always true). **A new dangerous switch is a table row plus a measurement of whether removal is in time; when in doubt it goes in the refused set.** Deliberately honoured: `--no-sandbox`, `--proxy-server`, `GOLDFINCH_AUTOMATION_ADMIN`. Not covered: the process-launcher family, a local attacker. Lists and reasons: `docs/RELEASING.md` *Launch switches*.
- **Crash log** (`crash-log.js`) records a closed EIGHT-key set by destructuring, source-scan pinned — no title/jar/cookie/page content can reach it. **`crashReporter.start()` must sit AFTER the dev-profile `setPath('userData')` redirect, with NO `submitURL`** and no `addExtraParameter`.
- **Single-instance lock + external URLs** (`main.js`, `app-lifecycle.js`, `chrome/external-urls-controller.js`): `app.requestSingleInstanceLock()` sits AFTER the dev `setPath('userData')` redirect (it is keyed on userData, so dev and installed coexist) and BEFORE `crashReporter.start(`/`registerAppLifecycle(` (`single-instance-lock-order.test.js`); the loser does `app.exit(0); process.exit(0)` before any side effect — never `app.quit()` (the `whenReady` chain would still run and write a snapshot), never a top-level `return` (TS1108). OS-handed URLs (cold argv, `second-instance`, macOS `open-url`) go through ONE main-side pending buffer (`filterLaunchUrls`: http/https only, deduped, cap 20, re-validated main-side) and the owner-routed `open-external-urls` channel — cold launch flushes to the FIRST created record (never `getLastFocused()`, which after a restore names the last), post-ready to last-focused with a paused-record fallback. The chrome opens them via `createTab(url, null[, { background: true }])` ONLY — **never `trusted`, never a container**, held behind a boot barrier released in `.finally` on the whole boot chain (`external-urls-wiring.test.js`), so they land after session restore. Logs name only the URL count.
- Frameless window: Close is `win.close()`, NOT `app.quit()`; the last close rides `window-all-closed`. Find-in-page is a floating overlay view, not chrome DOM (not in `tabViews`); the corner save prompt is the THIRD overlay view (find, sheet, save prompt — all per-window, none in `tabViews`).

## Release / CI

Both workflows are supply-chain hardened; preserve these invariants:

- **All `uses:` pinned to full commit SHAs** with a trailing `# vX.Y.Z` comment — never mutable tags. When bumping an action, **including accepting a Dependabot PR**, resolve the new version's commit SHA and pin to that (Dependabot proposes mutable tags; applying them verbatim regresses the hardening).
- **Least privilege**: top-level `permissions: contents: read`; only the `create-release`, `upload` and `publish-release` jobs escalate to `contents: write` per-job (`upload` alone also holds `id-token: write` and `attestations: write`, for its one tag-only `actions/attest` step over the verified installers) — **`build` never** (it runs project code: `contents: read`, no token or secret, checkout with `persist-credentials: false`, `--publish never`; it stages the five installers by exact name into a one-day artifact and the `upload` job, which runs no project code, verifies names and SHA-256 and uploads them). A release holds the five installers and no updater metadata; a manual dispatch runs everything but the upload. `test/unit/release-workflow-invariants.test.js` (text scan, no YAML parser) pins this; per-target `artifactName` in `package.json` is pinned to the README links by `test/unit/artifact-names.test.js`.
- **PR-equivalent checks run on the local Concourse instance, not GitHub Actions** (`ci/README.md`): `npm ci → test → typecheck → lint → npm audit --audit-level=high → package`, run automatically on every push to `main` (the `ci` job in `ci/pipeline.yml`) and pre-push against your working tree via `fly -t local-goldfinch execute -c ci/tasks/<task>.yml -i repo=.` (`test.yml` / `typecheck.yml` / `lint.yml` / `audit.yml` / `package-linux.yml`). `.github/workflows/ci.yml` runs the same suite but is `workflow_dispatch`-only — a deliberate manual fallback for when Concourse is unavailable, not a PR trigger. A high in a dev-only dep is fixed by bumping the dep, never by lowering the gate.

### Cutting a release (`build.yml`, on `v*` tag push)

Tag-driven — full flow in `docs/RELEASING.md`. Short form: the version bump arrives by **pull request**, then the **merged commit on `main`** is tagged: on a `release-prep/vX.Y.Z` branch, `npm version patch --no-git-tag-version` (runs the `preversion` PSL-freshness guard — refuses if the vendored snapshot is >90 days old, fix with `node scripts/update-psl.mjs` as its own reviewed commit — and the `version` hook that regenerates the README download links; creates no commit and no tag), commit by hand, PR, squash-merge, then `git switch main && git pull --ff-only`, `git tag -a vX.Y.Z` on that commit, `git push origin vX.Y.Z`. A **stable** tag whose commit is not reachable from the default branch is refused by `create-release` before any draft exists (compare endpoint; reachable, not "is the head"); a prerelease tag skips that check. Strict semver is enforced; a prerelease tag publishes as a GitHub prerelease. **Rollback is "publish the next patch version", never re-tag**: with immutable releases on (since `v0.19.15-rc.2`), a deleted release's tag name is spent (`gh release delete … --cleanup-tag` is only for a release published before immutability), and each `-rc.N` is used once. A hands-on Windows/macOS build comes from a manual dispatch run's one-day artifacts, not a public prerelease. Installers built by this workflow are meant to carry a provenance attestation (`gh attestation verify`, README *Verify your download*; releases up to v0.19.15 have none); the tag ruleset on `v*` (`release-tags`) and the immutable-releases setting are one-time repository settings the owner applied, both observed at the acceptance walk of 2026-11-17 (`docs/RELEASING.md`; Flight 3 flight log, leg 11): `v0.19.15-rc.2` is the first immutable release (`rc.1` predates the setting), the attestation step ran on all three candidates (five subjects, no `artifact-metadata: write` needed), and a stable-looking tag on a commit not on `main` was refused with no release created; **a stable tag on a `main` commit passing that check has not run yet** (the next real release is its first). `gh attestation verify`, `gh release verify` and `gh release verify-asset` succeeded on Linux with GitHub CLI 2.104.0 (not run on Windows or macOS). **Project-specific planning rules (this file, not `.flightops/` — those two files are synced from the plugin and overwritten on `init-project`, so a rule that lives only there is lost on the next sync).**
- A leg's live smoke test exercises **every existing apparatus primitive** against the leg's new state (census, windows, capture, evaluate, …) — not only the primitive the leg added.
- A design decision that installs a **global hook** (`crashReporter`, an `app.on` listener, a session-wide listener, …) lists which earlier spike premises it could change, and **re-runs** them in that leg.
- An AC that changes a **shared mechanism** (live regions, focus, the render/refresh cycle, the sheet) lists every existing feature sharing it and asserts they're unaffected (M22 F1: a scoped `aria-live="off"` silenced Access-keys announcements).
- **Verbatim extraction TDZ checklist item**: anything referenced above the construction site needs a getter or a hoisted declaration — a straight cut-and-paste of code into a new scope can silently turn a working reference into a `const`/`let` TDZ `ReferenceError`.
- **A write-targeting picker never defaults to a real destination** — a disabled placeholder option (Sortie 04 F3, squawk 0146).
- **Every AC that relies on an existing primitive is checked against that primitive's actual signature at design review** (Sortie 04: `openModal` has no submit-label setter).
- **A refusal that compares an IPC-supplied value rejects a non-string BEFORE comparing**, and its tests send an array and an object through the real store, not only a mock (Mission 23: a `===` guard on a key name was bypassed by a non-string the store then coerced, found at Flight 1's review and built again in Flight 2's `admin-key-name` leg).
- **Every claim that existing code already does something — in a design decision, a platform check or a leg's context — cites the call site that does it** (Mission 23 Flight 2: "the vault is locked at quit" rested on a comment about a hook that was never wired, and "an unknown session id gets the wrong status" was already handled; both fell to "show me the line").
