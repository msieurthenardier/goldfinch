# Leg: automation-input

**Status**: completed
**Flight**: [Vault and Automation Boundary](../flight.md)

## Objective

Input that automation injects no longer counts as the operator's: it cannot raise the vault picker at any tier, and from a jar-scoped key it cannot trigger the browser's own shortcuts.

## Context

- Flight DD4 (read it in full). Mission findings 5 (the chrome-side half) and 17b.
- **Q2 is answered: yes.** In the `vault-gesture-trust` run on Electron 45.3.2 (2026-11-14, `tests/behavior/vault-gesture-trust/runs/2026-11-14-20-46-39.md`, step 6) the "real click" was an automation `click`, and it produced `[vault-gesture] accepted` and raised the sheet. Flight 1's own comment at the witness says so: "an MCP `click` is injected below the page, so it counts" (`src/main/guest-wiring.js`, the `input-event` listener in `wireTabViewEvents`). An accepted gesture mints a picker context and pushes its id to the chrome, where admin script can read it and call the fill channels — for cards and identities too, which automation's own `vaultFill` deliberately excludes. A jar-scoped key can raise the sheet on its own jar's tab as well, though it cannot read the chrome.
- **Q3 is open and is this leg's first measurement**: which of the browser's shortcuts fire when a jar-scoped key calls `pressKey` with a chord. By reading: `contents.on('before-input-event', …)` for web guests runs `handleCrossView`, then `handleChromeShortcut(event, input, 'web', contents)`, then F12 → `toggleDevTools`, with no knowledge of who sent the key.
- **Where the tier is known — and where it is not.** The per-session engine is built by `getEngine({ allowInternal: identity === 'admin' })` in `mcp-server.js`, wrapped by `scopeEngine` for a jar key. But `allowInternal` is **not** the tier: the dev-only chrome channel's engine (`app-lifecycle.js`) deliberately never sets it (its comment explains why), and it is not a jar key. So the tier travels as its **own explicit engine option** (`jarTier: true`), set at exactly one place — the server's `getEngine` call when `identity !== 'admin'` — and surfaced through `deps()`. The dev channel's engine and the admin session's engine are non-jar. Every input helper in `src/main/automation/input.js` (`sendInput`, `actOn`, `actOnPaced` → `click`, `typeText`, `pressKey`, `dragPointer`) ends in `wc.sendInputEvent(ev)`; `actOnPaced` spreads its events across turns of the event loop.
- **The witness** (`src/main/vault/gesture-witness.js`, `createGestureWitness({ now, trace })`) records the last real left press, left release and right press per tab from `input-event`. The verifier (`gesture-verifier.js`) refuses with `reason=no-real-input` when there is no fresh press and release. Trace line formats are contracts of `vault-gesture-trust` (flight DD9) — this leg adds **no new reason value**.
- **Not known before the leg**: whether `input-event` and `before-input-event` are emitted synchronously inside `sendInputEvent` or on a later turn. The design below does not depend on synchrony, but the size of the trailing allowance does. Measured first.
- This leg owns the re-authoring of `tests/behavior/vault-gesture-trust.md` (leg `electron-45` already made its page-sent steps conditional on the reach result; this leg changes step 6).
- Budgets: do not touch `src/renderer/renderer.js`. `main.js` gets construction and wiring only.

## Edge Cases

- **A helper throws mid-sequence** (tab closed between events): the release still runs; `forget` on `destroyed` clears the tab's counts.
- **Overlapping injections into one tab** (two sessions): counts, not flags — the tab reads as injecting until the last release plus the allowance.
- **A jar injection and an admin injection overlap in one tab**: the jar count is up, so shortcuts are suppressed for that window, including the admin's. Accepted; note it, and unit-test the overlap.
- **A paced drag** holds the count for its steps × the step delay plus the allowance; the docs state the figure, since it is how long the operator's own click in that tab can be ignored.
- **The operator clicks the fill icon while automation is injecting into that tab**: ignored once (they click again). Accepted in DD4.
- **The operator presses a shortcut in a tab while a jar key is injecting into it**: lost once. Accepted in DD4.
- **`typeText` into a field followed by the page calling `element.click()` on the icon**: already refused (`element.click()` never reaches `input-event`).
- **Automation clicks a page element and the page moves the icon under the next real click**: unchanged from Flight 1's accepted residual; not this leg.
- **The allowance is too short on a loaded machine**: an injected event delivered after the count cleared would be witnessed. AC1(c) sizes it; if delivery turns out to be asynchronous with a long tail, stop and report `[BLOCKED:async-input-delivery]` with the measurements rather than picking a large number — the design would need to change (for example, matching on event identity).
