# Leg: electron-45

**Status**: completed
**Flight**: [Vault and Automation Boundary](../flight.md)

## Objective

Move Goldfinch from Electron 44.10.0 to 45.3.2 and prove, on the new runtime, every behaviour this codebase is known to depend on — changing nothing else.

## Context

- Flight DD1. Operator instruction (2026-11-14): the bump is flown inside this flight, first. Dependabot's PR #286 names 45.3.0; two patches have shipped since (45.3.1 certificate distrust, 45.3.2 a fix for cookies set shortly before quit not being saved). The PR is not merged; it is closed as superseded when the flight's PR merges.
- Electron 45.0 moves Chromium 152 → 156 and the bundled Node 24.18 → 24.22. The documentation review (flight log → *Electron 45*) found no breaking change in an API this code uses. That review read release notes; it ran nothing. This leg is the measurement.
- Two standing rules in CLAUDE.md apply to every Electron major bump: the full store suite is re-run (`node:sqlite` is experimental), and the `third-party-cookie-isolation` behavior spec is re-run (an unknown `enable-features` name is silently ignored, so a renamed feature would make isolation fail open).
- `npm test` runs under the system Node (22.22), **not** Electron's. Passing it says nothing about `node:sqlite` in the shipped runtime. The store suites must also run under Electron's own Node (`ELECTRON_RUN_AS_NODE=1`).
- Flight 1 built trust on runtime behaviour: the click witness listens to `input-event`; the vault observer runs in an isolated world via `executeJavaScriptInIsolatedWorld`; the media proxy is keyed on the main frame's `frameToken`; the gate compares frame-tree node ids. Each is re-proven here by its behavior spec.
- **This leg changes no behaviour.** A defect found on 45 that is not caused by the bump is a squawk. A defect caused by the bump is fixed here only if the fix is small and local; otherwise see Edge Cases.
- Division of work: the Developer does the bump, the gates, the bundled-runtime suites, the scripted live smoke and the documentation. The Flight Director then runs the behavior specs (Executor and a separately spawned Validator). The leg lands only when both halves pass.

## Implementation Guidance

1. **Baseline** (AC1) on the untouched tree. Record counts.
2. **Bump**: `npm install --save-dev --save-exact electron@45.3.2`. If a newer 45.x patch exists at that moment, stay on 45.3.2 and note the newer one in the log (the flight spec allows a newer patch only by Flight Director decision). Verify the pin is exact and the lockfile diff is confined.
3. **Static gates** (AC3). Read Electron 45's `electron.d.ts` for `MessageBoxOptions.signal` and `RelaunchOptions` while there (AC6 last line, AC8).
4. **Store suites under the bundled Node** (AC4). Find the files with `grep -rln "node:sqlite\|app-db\|history-store" test/unit`. Try `ELECTRON_RUN_AS_NODE=1 npx electron --test <files>`; fall back as AC4 allows.
5. **Regenerate the preload bundles** (`npm run build:preload` — check what the dev launch already does) and **boot** (AC5). Read the launch output for errors before driving anything.
6. **Live smoke** (AC6). Write the script(s) in the scratchpad directory, modelled on the existing behavior-run scripts' use of `scripts/lib/mcp-client.mjs`; consult `docs/dev-testing.md` for launch states, key capture and the fixture recipes. Run fixtures on their documented ports. Downloads land in the operator's real downloads folder: use a run-unique prefix and delete by exact name; never open a downloaded file. Do not unlock or type into any vault sheet.
7. **Pack** (AC7).
8. **Re-date** (AC8) and **docs** (AC9), then `npm run format` and the gates once more.
9. **Flight log**: add the leg entry with the re-verification table, every measured value, every deviation, and every item not run with its reason. Answer flight Q1 there in one paragraph.
10. Do not commit. Do not push. Mark the leg `landed` and signal `[LAND:leg]` only if AC1–AC10 hold; if any fails and is not fixable under Edge Cases, leave the leg `in-flight`, report with `[BLOCKED:<reason>]`.

## Edge Cases

- **A bump-caused failure with a small local fix** (a renamed option, a typings change, a preload global that is now missing): fix it, add or adjust the unit pin, list it in the flight log with the Electron change that caused it.
- **A bump-caused failure with no small fix** — `node:sqlite` API or behaviour change, the cookie-blocking feature no longer recognised, `input-event` not firing, a native-surface regression, `electron-builder` unable to pack 45: **stop**. Do not work around it, do not downgrade on your own. Leave the tree as it is, record exactly what failed and how to reproduce it, and signal `[BLOCKED:electron-45-<short-reason>]`. The flight's Divert rule (revert to 44, operator decides) is the Flight Director's call.
- **`npm install` pulls a different patch or touches unrelated packages**: reset the lockfile and redo with `--save-exact`; if npm insists on unrelated changes, list them and say why.
- **The copied dev profile fails to open on 45** (a store or the vault manager): keep the failing copy, record the error, signal blocked. If no dev profile exists on this host, record that and run the check against a profile freshly created by 44.10.0 before the bump.
- **WSLg rendering differences** that are visible only by eye are out of this leg's reach: note anything suspicious for the HAT; a `captureWindow` screenshot is supporting evidence, not a pass.
- **A defect that also reproduces on 44.10.0** is not this leg's: describe it in the flight log for the Flight Director to log as a squawk.
- **`npm audit`** reporting a new high caused by the bump is a failure of AC3, fixed by bumping the dependency, never by lowering the gate.
