## Objective

The main process asks GitHub once a day whether a newer stable release exists, believes only a validated version number from the answer, holds the result as state that the chrome and internal pages can read and are told about, and offers a no-argument way to open the release page — with a setting that turns all of it off.

## Acceptance Criteria

- [ ] **AC1 — The pure module** (`src/shared/update-version.js`; unit tables, no Electron):
  - `parseStableTag(tag)` → a bare version string or `null`. Accepts exactly `v` + `MAJOR.MINOR.PATCH` with no leading zeros; refuses a prerelease or build suffix, a missing `v`, whitespace, a non-string, anything over 64 characters, and numbers past `Number.MAX_SAFE_INTEGER`.
  - `compareVersions(a, b)` → semantic-version precedence for the forms the app can be running: `MAJOR.MINOR.PATCH` and `MAJOR.MINOR.PATCH-prerelease` (a prerelease sorts **below** the same core; prerelease identifiers compared by the standard rule — numeric identifiers numerically, numeric below alphanumeric, a longer list above its prefix). An unparseable running version makes `isNewer` answer `false`.
  - `isNewer(available, current)`. Table includes: `0.19.16` over `0.19.15` yes; equal no; lower no; `0.19.15` over `0.19.15-rc.1` **yes** (the acceptance walk depends on it); `0.19.15` over `0.19.16-rc.1` no; `0.20.0` over `0.19.99` yes; `1.0.0` over `0.99.99` yes; `0.19.10` over `0.19.9` yes (numeric, not text).
  - `releaseUrlFor(version)` → `https://github.com/<slug>/releases/tag/v<version>`, built only from a version that re-passes the stable pattern (`null` otherwise). `LATEST_RELEASE_API_URL` and the slug are constants here.
  - `readLatestTag(bodyText)` → the validated bare version or a reason code: a body over the size cap, not JSON, not an object, `tag_name` missing or not a string, or failing `parseStableTag`. Nothing else in the body is read.
  - **Drift guards**: the slug equals `package.json` `build.publish` `owner/repo`; the stable pattern's core is the same three numeric groups as the workflow's rule (a test reads `.github/workflows/build.yml`, finds the `semver=` line and asserts every tag the app accepts also satisfies the workflow's expression, over the test table — it throws rather than passing if the line is not found).
- [ ] **AC2 — The checker** (`src/main/update-check.js`; Electron-free: `fetch`, `getVersion`, `isEnabled`, timers, `now`, `onChange`, `url`, `trace`, the initial delay and the interval are injected):
  - **One request per check**: `GET` with `credentials: 'omit'`, `redirect: 'error'`, `referrerPolicy: 'no-referrer'`, `cache: 'no-store'`, the caller's headers exactly `User-Agent: Goldfinch-update-check` and `Accept: application/vnd.github+json` (the unit test asserts the options object; what the network stack adds — `Accept-Encoding` and the like — is judged live, AC10 step 1), an abort signal, and a 15-second overall limit.
  - **Reading the answer**: status must be exactly 200; the body is read as a stream and the read is abandoned (request aborted) once more than 512 KiB has arrived — a declared length is not trusted in either direction; then `readLatestTag`; then `isNewer` against `getVersion()`.

## Edge Cases

- **`net.fetch` will not send the custom `User-Agent`, or adds headers of its own** (squawk 0197 shows the app token reaching some requests): the fixture's log decides. If the fixed value cannot be sent, or a `goldfinch/<version>` token appears, stop and signal `[BLOCKED:user-agent]` with the observed header — the request must not carry the app version.
- **`credentials: 'omit'` is not honoured by `net.fetch`** (a cookie is sent in step 2): signal `[BLOCKED:credentials]`; the fallback (a dedicated in-memory session) was deliberately rejected at flight design and needs a Flight Director decision.
- **`redirect: 'error'` or `cache: 'no-store'` is not honoured** (the second loopback port receives a request; a cached tag is reported): signal `[BLOCKED:fetch-options]` with the observation. `net.request` documents these options and is the likely fallback, but choosing it is a Flight Director decision.
- **The repository is renamed or moved**: GitHub answers 301, which is `redirect` every time — silent, permanent, and by design (a redirect is never followed). Stated in the docs.
- **The packaged branch** (override ignored, the real address) is covered by unit test only; no packaged build is driven in this leg. The acceptance walk is its live check.
- **A proxy that demands sign-in** (407): same as 401 — silent `http-407`.
- **The system clock jumps or the machine sleeps for days**: the 24-hour timer simply fires late; no catch-up burst. Stated in the docs, not engineered around.
- **`app.getVersion()` in a dev build** is `package.json`'s version; fine.
- **Two windows, a recovered chrome, a settings tab opened later**: all read through `update:get-state` at boot in leg `update-notice`; this leg only guarantees the read is right at any time.
- **A release whose tag is stable but lower than the running version** (a rollback upstream): `current`, nothing shown.
- **The response is valid but `tag_name` is enormous**: refused by the 64-character limit before any pattern runs.
- **Anything needing a design call**: `[BLOCKED:<reason>]`.
