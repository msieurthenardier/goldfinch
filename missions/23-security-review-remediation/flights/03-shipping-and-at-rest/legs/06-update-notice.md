# Leg: update-notice

**Status**: landed
**Flight**: [Shipping and At-Rest](../flight.md)

> Developer design review 2026-11-17 (against leg 05 as built): **approve with changes**, incorporated — the kebab state guards against a boot read overwriting a newer push and has a reset for tests; the model's own import needs its own route on the settings host; the version check reuses `parseStableTag('v' + …)` so no landed file changes; two existing behavior specs assume the kebab's default rows and must run with the override unset; keyboard-opening the kebab lands on the update row when it is present (accepted); the kebab's real-trigger proof is by eye and its dispatch link gets a unit case; the behavior spec was corrected in six places (coordinates for `click`, the Settings and second-window recipes, stdout capture, key re-capture after relaunch, which rows the hidden notice actually discriminates, the fixture's exact failure bodies).

## Objective

The operator can see which version they are running, is told in Settings and in the kebab menu when a newer release exists, can open its release page from either place, and can turn the check off — all rendered from the state leg `update-check` already holds.

## Context

## Acceptance Criteria

- [ ] **AC1 — One pure model for both surfaces** (`src/shared/update-notice-model.js`, DOM-free, never throws): `updateNoticeModel(state)` → `{ versionText, noticeText, showNotice, openLabel, kebabLabel }`. `versionText` is `Goldfinch <current>`; with a newer release, `noticeText` is `Version <available> is available.`, `openLabel` `View release notes`, `kebabLabel` `Update available — <available>`; otherwise `showNotice` is false and the notice strings are empty. It shows a notice **only** when `available` is a string for which `parseStableTag('v' + available)` (the existing export of `update-version.js` — that file is not changed) returns the same string **and** `releaseUrl` is non-null; `versionText` is `Goldfinch` alone when `current` is not such a string (never "Goldfinch undefined") — anything else (missing state, wrong types, a version with other characters) is "no notice", so no unexpected text can reach either surface even if the state were wrong. Unit table covers each branch and hostile shapes (`available: '<b>x'`, an object, `null` state).
- [ ] **AC2 — Settings → About.** The placeholder sentence is replaced by: `#about-version` (always, from the state's `current`); `#about-update-status` and the button `#about-update-open` (present in the markup, `hidden` unless the model shows a notice); a checkbox `#update-check-enabled` labelled "Check for new versions" with the note `#update-check-note`: "Asks GitHub once a day whether a newer release exists. Nothing is downloaded or installed." The controller is a new IIFE in `settings.js` following the two precedents: reads `updateGetState()` at load, follows `onUpdateStateChanged` (handle removed on `pagehide`, `{ once: true }`), **patches in place** (the button is never rebuilt, so it keeps focus when a push arrives while focused); the checkbox reads `settingsGet('updateCheckEnabled')`, writes `settingsSet`, follows `onSettingsChanged`. The button calls `updateOpenReleasePage()` with no arguments and does nothing else. The model is loaded like the default-browser row model — a `<script src="update-notice-model.js" type="module">` tag beside the existing ones and a flat-specifier import in `settings.js` (`// @ts-ignore` on the line before the `from`) — with **two** new routes on `internal-page-map.js`'s settings host: the model **and** the `update-version.js` it imports (no settings-host shared module has had an import of its own before; an unrouted one 404s at page boot). A test pins that every `import … from './x.js'` inside a shared module routed on an internal host is itself routed on that host. `internal-page-route-closure.test.js` and `settings-page-shared-scripts.test.js` green. No inline script or style; `textContent` only; the page's CSP is untouched.
- [ ] **AC3 — The kebab item.** `overlay-menus.js` holds the latest update state in module scope, set by an exported setter. `createChromePageActions`' construction (once per chrome boot, `renderer.js`, with `window` passed in, before any kebab can open) subscribes `onUpdateStateChanged` and then reads `window.goldfinch.updateGetState()` once, feeding that setter — each guarded by `typeof … === 'function'`, so the existing harnesses that pass `window: { goldfinch: {} }` need no change. **The boot read never overwrites a push**: once a push has been applied, a read result that arrives later is dropped (unit case). The chrome bridge's `onUpdateStateChanged` returns no handle; a boot-once subscription needs none. An exported reset (or the setter with `null`) returns the module to no-notice, and the test file calls it in `afterEach` — module-scope state must not leak between cases. `buildKebabModel()` — still **no parameters** — returns today's list unchanged when there is no notice, and with one extra first row `{ id: 'update', label: <kebabLabel> }` followed by a separator when there is. `kebabActions.update` calls `window.goldfinch.updateOpenReleasePage()`. Nothing existing is reordered or renamed; no accelerator is bound. One accepted behaviour change: the kebab opens with `startIndex` 0 (pointer) or -1 (keyboard), which are positional, so while a notice exists a keyboard open lands on the update row instead of *New window*. No sanitiser, allowlist or length cap applies to a kebab id or label (`overlay-dispatch.js` looks the id up in `KEBAB_ACTIONS`; the 24-character cap is on an activation *value*; labels are text nodes).
- [ ] **AC4 — Tests for the kebab.** The drift guard is rewritten deliberately as: `kebabActions`' keys equal the default model's ids **plus `update`**, and with a notice set the model's ids equal exactly `kebabActions`' keys. New cases: default model byte-for-byte what it was (deep-equal to a literal copy of today's list); with a notice the first two rows are the item and a separator and the rest is unchanged; state cleared → the item goes away; the setter ignores a state the model rejects; `kebabActions.update` invokes the bridge with **no arguments**; and in `overlay-dispatch.test.js`, a case that sends a kebab activation with id `update` through the real dispatch into the real `kebabActions` (mirroring the existing `automation` case). `renderer-kebab-wiring.test.js` passes unmodified. **What this proves and does not**: the model, the action and the dispatch link, at unit level. That the item appears in the rendered menu only when a release exists, and that clicking it opens the page, is `[by-eye]` in leg `hat-and-alignment` — the sheet cannot be read or clicked by automation, and no dispatch function is in the evaluate seam (none is added).
- [ ] **AC5 — Budgets and shared mechanisms.** `git diff --stat -- src/renderer/renderer.js` is empty; `seam-contract.test.js` passes with the seam at 41. The sheet's own code (`menu-overlay.*`, `menu-controller.js`, `sheet-accelerator.js`) is untouched — the kebab is still an ordinary menu model. Settings page: no `aria-live` is added or changed anywhere (project rule after a scoped live-region change once silenced another section's announcements); none of the page's four existing `role="status"` elements is changed; every other Settings controller's ids are unchanged (`git diff` of `settings.html` shows additions inside `#about` only).
- [ ] **AC6 — Accessibility.** The checkbox has a programmatic label and its note is associated (`aria-describedby`); the button's accessible name includes the version ("View release notes for version 0.19.16" via `aria-label` or visible text); the hidden notice and button are really hidden — computed `display` is `none` (a `display` rule on `.settings-btn` would defeat the bare `hidden` attribute; hide the way `#default-browser-make-default` does and check the computed value in the smoke). `npm run a11y -- --target=goldfinch://settings`, run against a dev launch that has the fixture and the override so the notice is showing, reports no new finding; no state needs registering in the audit script.
- [ ] **AC7 — The fixture.** `tests/behavior/fixtures/update-check/server.cjs`: a loopback server (fixed default port, overridable) that answers the override address according to a mode set by a control request — `higher`, `equal`, `lower`, `prerelease` (valid JSON, a prerelease tag → `bad-tag`), `malformed` (valid JSON, `tag_name` a string without the `v` → `bad-tag`), `not-json` (→ `bad-json`), `redirect` (a `302` to a **second listening port the fixture also owns and logs**), `http-500`, `oversize` (a 2 MiB body) — with versions computed relative to the one in `package.json` so the spec never hard-codes a version; logs every request's method, path and headers; and exposes the log and a reset through control paths. Same conventions as the existing fixtures in that directory (CommonJS, no dependency, a header comment saying which spec uses it).

The leg lands when the run passes, or with each failing row resolved (a product fix, or a spec correction recorded in the run log). The row that clicks `#about-update-open` drives the open from the **real control**, not the bridge call.

## Edge Cases

- **A push arrives while the kebab is open**: the open sheet is not re-rendered; the next open is right. Accepted.
- **A push arrives while the About button has focus and the notice goes away** (setting turned off in another window): the button becomes `hidden`; focus falls to the document as with any hidden focused control — move it to the checkbox rather than lose it.
- **The state read rejects** (chrome recovery mid-boot, a destroyed frame): treated as no notice; the push or the next boot corrects it. Never an unhandled rejection.
- **`renderer.js` would need a line after all**: stop — extract something first or signal `[BLOCKED:renderer-budget]`; never compact.
- **A new `src/renderer/pages/*.js` file** would need its own entry in `eslint.config.mjs`'s module list; the controller goes in `settings.js` to avoid that — if it is split out anyway, add the entry.
- **The spec run needs a tab that tries to load GitHub**: the dead proxy makes that load fail locally; the tab's address is the assertion. (The proxy matters for that tab and for any outside tabs the dev profile restores; the update request itself goes to loopback, which bypasses it.)
- **Existing specs that assert the kebab's default rows** (`tests/behavior/kebab-menu.md`, `tests/behavior/multi-window-shell.md`: eight items, *New window* first) hold only while no notice exists — true for any dev launch without `GOLDFINCH_UPDATE_CHECK_URL`. Add one precondition line to each saying so; do not otherwise edit them.
- **The update label is wider than the kebab's minimum width**: appearance is `[by-eye]`; listed for the walk.
- **Anything needing a design call**: `[BLOCKED:<reason>]`.
