# Leg: welcome-surface-and-home-routing

**Status**: completed
**Flight**: [The Welcome Surface](../flight.md)

## Objective

A tab record can exist without a web view and show a chrome-rendered welcome surface in the guest slot; every new-tab path routes to such a tab when the home page is unset; the surface's home-page block and the Settings page's new Clear button both write the preference through validated channels; the record acquires its view in place on the first navigation from any entry point; `homePageCache` is boot-seeded and raw (squawk 0005 closed) and the `HOMEPAGE` constant is gone with its three coalescing sites; a viewless tab shows no dead controls and refuses tear-off honestly; `openSiteSettingsTab` targets Settings specifically — verified end-to-end on an existing profile by `welcome-home-routing` and by re-running `search-engine-upgrade` (squawk 0006 closed).

## Edge Cases

- **Broadcast before seed resolves**: both call `setHomePage` with identical source data — benign; no ordering machinery.
- **Welcome record closed before any attach**: `closeTab` skips `tabClose`, removes the button, backfills. Its pending query (leg 2) dies with it.
- **`attachView` racing a second navigate**: guard with `tab.attaching = true` until `tabCreate` resolves; a second `navigate` during that window updates the URL via `tabNavigate` once `wcId` arrives (queue one pending URL, not many).
- **Window opened at boot with `restoreTabs`**: no welcome tab is added (boot path branch); with `bootTab === false` nothing opens either — unchanged.
- **`homePage` set to `null` while a welcome tab is active in another window**: the broadcast hides nothing (the tab is already welcome); setting it non-null hides the home block on every open welcome tab (controller listens to `onSettingsChanged`) — a welcome tab whose only reason was `'home'` then attaches to the new home page (DD7), which is the same-tab behavior the user expects after setting it from Settings.
- **Burner welcome**: the record's jar is the burner; the bookmarks bar stays suppressed (existing burner rule — `renderer.js:207`), so the address bar is the escape hatch, as the mission ruled.
- **Keyboard reorder** of a welcome tab works (`commitTabMove`); mouse drag is refused by the `wcId == null` guard (DD8) — do not "fix" the guard.
