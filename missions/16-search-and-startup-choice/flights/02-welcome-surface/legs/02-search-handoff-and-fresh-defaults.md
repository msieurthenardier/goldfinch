# Leg: search-handoff-and-fresh-defaults

**Status**: completed
**Flight**: [The Welcome Surface](../flight.md)

## Objective

A search typed with no engine chosen lands on a welcome tab that shows the pending query and offers only the engine choice, from both entry points (address bar and the context-menu "Search for …"); choosing an engine writes the preference and runs that search in that same tab; the pending query is length-capped and never evaluated; Settings gains an engine Clear button; fresh profiles start with both preferences explicitly `null` (repair-to-unset, no version bump) so first launch shows the welcome surface with both blocks; and every new-tab welcome offers exactly the preferences that are missing. Verified by `welcome-search-handoff`, `welcome-first-launch`, and re-runs of `new-tab-default-routing` and `search-engine-preference` after their fixture preconditions are re-authored for the new fresh-profile state.

## Edge Cases

- **Search typed on a welcome tab that already carries a pending query**: the new query replaces the old (latest wins), the heading updates.
- **Engine chosen with a pending query while the home page is also unset**: run the search (attach) — the home block is moot for this tab now; the next new tab will still show the home block.
- **Engine set from Settings (or another window) while a pending-query welcome tab is open**: the broadcast re-renders; the block disappears and the pending search runs in that tab (DD3: a search typed before an engine was chosen is not lost).
- **Home page set while a search-only welcome tab is open**: nothing changes for that tab (its unset block is the engine); it attaches only when the engine is chosen.
- **Both unset, user types a URL on the first-launch welcome**: attaches; both preferences stay unset; the next Ctrl+T shows both blocks again.
- **Empty or whitespace-only input**: guarded in `navigate` (new — there was no such guard; Enter on an empty bar used to search for `''`). No handoff, no navigation, no welcome tab.
- **`capPendingQuery` on a 2048+ char selection from `sel:search`**: truncated before it reaches the record; the heading shows the truncated text.
- **Repair path**: a stored `searchEngine: "kagi"` now repairs to `null` → the welcome surface asks on the next search — the criterion-10 outcome. Existing rows pinned at `google` by Flight 1 are untouched.
