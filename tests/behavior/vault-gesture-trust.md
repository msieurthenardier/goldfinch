# Behavior Test: Only a real click on the fill icon raises the vault sheet

**Slug**: `vault-gesture-trust`
**Status**: active
**Created**: 2026-11-13
**Last Run**: 2026-11-14 — pass (reduced) on Electron 45.3.2, after leg `automation-input`: steps 1, 2, 4, 6, 11 pass (an automation click on the icon is refused); reach recorded false; steps 3, 5, 9, 10 not exercised; 6b, 7, 8 by-eye, not performed, [run log](vault-gesture-trust/runs/2026-11-14-22-29-48.md)

## Intent

Verify that neither a page nor automation can raise the vault picker (or its unlock sheet) by itself. Mission 23 Flight 1 found (on Electron 44.10.0) that a page in a tab holding the guest preload's IPC object can send the fill-icon gesture message with no click at all, including from a background tab; on Electron 45.3.2 the known probe no longer reaches the object (not proven closed). After leg `vault-fill-trust`, the main process witnesses real pointer input on each tab and honours the gesture message only when it saw a real click inside the icon's reported box, in the active tab, at most once per click. After leg `automation-input` (Mission 23 Flight 2), input that **automation injects is not a real click**: main counts what automation is injecting into each tab and the witness ignores it, at every tier, so an automation `click` on the icon is refused and no automation tier can raise the picker. The accept path - a physical click raising the sheet - can therefore no longer be driven by this apparatus and is walked by the operator (`[by-eye]`, step 6b). This needs a behavior test because the property exists only across the real process boundary, with real injected input and a real guest sender.

## Preconditions

- Goldfinch running via `GOLDFINCH_AUTOMATION_DEV_MINT=1 GOLDFINCH_AUTOMATION_ADMIN=1 GOLDFINCH_IPC_TRACE=1 npm run dev:automation`, stdout captured to a file the Executor can read; admin key from the printed `AUTOMATION_DEV_MINT` line; client attached with `connectAutomation()` (`scripts/lib/mcp-client.mjs`). **Never** a registered MCP server.
- The dev profile's vault is **set up** (locked or unlocked — both raise a sheet: the unlock sheet when locked, the picker when unlocked). The run never types a master password.
- The fixture server `tests/behavior/fixtures/page-containment-probe/server.cjs` on `127.0.0.1:8231`, serving `gesture.html`: a login form, plus the same hook as `refusal.html` that lets the page keep the IPC object it is handed, and three functions the run calls by `evaluate` — `sendGestureNoClick()`, `sendGestureWithBox(box)`, `sendIconMenuNoClick()`.
- **Non-vacuity is established outside this spec.** Leg `vault-fill-trust` recorded one run of `sendGestureNoClick()` against the pre-change build in which the sheet opened. The refusals were demonstrated live on Electron 44.10.0 ([run log](vault-gesture-trust/runs/2026-11-14-04-02-54.md), 11/11). On Electron 45.3.2 the known probe does not reach the IPC object (run 2026-11-14-20-46-39: `reached: false`), so the page-sent steps cannot run there; on such a runtime the verifier and witness are carried by the unit tests (`test/unit/gesture-verifier.test.js`, `test/unit/gesture-witness.test.js`, `test/unit/picker-context.test.js`, `test/unit/vault-gesture-policy.test.js`). **A run recording `reached: true` on a runtime where the previous run recorded `false` must be called out at the top of the run log: the route to the object reopened.**
- **Run status**: a run with `reached: false`, every step that does not need the object passing, and the page-sent steps NOT EXERCISED is status `pass (reduced)`, not `partial`. NOT EXERCISED is never counted as a pass.
- **Apparatus (act)**: MCP `click` (input injected below the page - since leg `automation-input` it is **not** witnessed as real input at any tier; it is how the spec proves the refusal), `evaluate` on the tab for the page's own functions and for script-synthesised clicks, `activateTab`. **Apparatus (observe)**: `enumerateWindows()` `sheetVisible`; the captured stdout's `[vault-gesture]` and `[ipc-gate]` trace lines; `readDom` / `captureScreenshot` of the tab for the icon. `captureWindow` does not composite the sheet, so sheet presence rests on `enumerateWindows().sheetVisible`.
- **Unobservable, not asserted here**: which card the sheet shows and anything inside it; the native icon menu. Step results that would need them are marked `[by-eye]` and are not judged.
- **Verdicts an unattended run can no longer reach, and where they are carried.** With automation input not witnessed, a run cannot produce a real click, so these are carried by unit tests, not by this spec: `outside-box`, `bad-box` and `rate` by `test/unit/gesture-verifier.test.js` (`bad-box: ...`, `outside-box: ...`, `rate: ...`, and the refusal-order test); consume-on-accept and a refusal consuming nothing by `test/unit/gesture-witness.test.js` (`a real click inside the box is accepted ... CONSUMED`, `a REFUSAL consumes nothing`); the witness ignoring injected input at every tier, an earlier real click surviving an injection, and a real release during an injection being dropped by `test/unit/guest-wiring.test.js` (`automation-input AC5: ...`). The physical accept, the consume and the tab-switch close are `[by-eye]` steps 6b-8.
- **Accepted residual, not a failure**: a page that sends the message itself can claim a box around a real click the operator made elsewhere on that page. No step asserts otherwise.

## Out of Scope

- Everything inside the sheet: the destination line, arming, no selected row, the card / identity confirmation, the certificate warning, and an actual fill — `[by-eye]` in the `hat-and-alignment` leg.
- A physical pointer click (the apparatus injects input, which is no longer witnessed as real) — steps 6b-8, walked by the operator in the HAT leg.
- A real right-click on the icon: it opens a native menu the apparatus can neither observe nor dismiss. The right-button witness is unit-tested and smoke-tested with an app restart in leg `vault-fill-trust`.
- A page claiming a box around a real click made elsewhere on it — the accepted residual; the picker's own controls are the defence.
- Capture (`guest-vault-capture*`) and the save prompt.
