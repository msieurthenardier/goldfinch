**Source-grep as corroboration — endorsed with a condition.** The Validator accepted grepping the source for a literal string to settle character-level wording claims inside refused-automation sheets, **provided it is paired with rendered evidence and never substituted for it** — source can diverge from the running build via a stale build, a feature flag, or a different code path than the instance loaded. Used correctly here.

**The `navigate()` fragment asymmetry — apparatus note with an open follow-up, deliberately not closed.** Adding a fragment is same-document; removing one reloads. Per the URL/History spec both directions differ only in fragment and should behave symmetrically. The Executor scoped it correctly as outside this spec and did **not** diagnose which layer owns it — it may be an artifact of the MCP `navigate` tool calling `loadURL` unconditionally, or it may reflect something goldfinch's own address-bar/history handling does. The Validator's ruling: record it as an apparatus note **but flag it as an open follow-up rather than closing it there**, because if the same asymmetry reproduces via direct user action — manually editing the URL bar to strip a fragment, or a back-button transition — that is a genuine product behaviour with implications well beyond the star, e.g. an unwanted full reload discarding page state. **Recommended follow-up: determine whether the asymmetry reproduces without the MCP tool in the loop.**

**Operator-attestation hygiene, validated twice more.** The standing rule promoted out of the `bookmarks-bar` run — verify attested targets by immutable identifier against a snapshot banked immediately before the action — paid off twice here. At checkpoint 8 the operator did not know which window they had acted in, and the id-level diff answered it definitively with no re-run. At checkpoint 6 a verbal transcription of a UI string diverged from the implementation, and a source grep settled it. In both cases a name- or recall-based check would have been ambiguous or wrong.
